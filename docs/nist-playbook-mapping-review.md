# NIST AI RMF mapping review

Reviewed 15 Oct 2026 against the official subcategory statements in the
[NIST AI RMF Playbook](https://airc.nist.gov/airmf-resources/playbook/) (data:
`client/src/data/nist-playbook.json`, generated by `scripts/generate-nist-playbook.mjs`).

**Method.** For each of the 27 controls in `CONTROLS` (`client/src/data/governance.ts`) the title
and description were read, then compared against the outcome statement of every candidate
subcategory. A subcategory is cited only where its **statement** covers the control; the
Playbook's suggested actions were used as secondary support, and that is marked *(action)*
below. 1–3 subcategories per control. Where nothing fits, no NIST mapping is cited.
IDs use NIST's own form (`GOVERN 1.1`, not `GOV 1.1`). `nist-playbook.test.ts` fails if any
cited id does not exist in the Playbook data.

The AI RMF is not a security-control catalogue. Infrastructure controls (access control,
encryption, network isolation) have no dedicated subcategory; they are mapped to
MEASURE 2.7 only, which is an indirect fit, and flagged below.

## Other references checked

- `AI-GOVERNANCE-MAP-MASTER-ARCHIVE.md` and `NHID-CLINICAL-MASTER-ARCHIVE.md` refer to NIST at
  function level only (GOVERN / MAP / MEASURE / MANAGE); no subcategory ids to verify. The archive's
  "GOV/MAP/MEASURE/MANAGE function codes" wording was updated to the canonical names.
- `matrix.ts`, `exports.ts`, the NHID sections and README carry no subcategory ids. The test scans every
  export of `governance.ts` and `matrix.ts` for anything that looks like a subcategory reference
  (including `GOV 1.1`, `MS 2.5` and similar) and fails unless it is canonical and exists.
